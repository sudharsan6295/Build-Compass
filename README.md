# Build Compass

A vendor-neutral framework for deciding whether an organisation should **build its own software with AI** or keep buying, subscribing to or outsourcing it — and, if the answer is build, for designing, vibe-coding, testing, deploying and supporting it safely.

**Live page:** https://sudharsan6295.github.io/ai-build-framework/

## What's inside

- **10 phases** in four stages (Decide → Prepare → Deliver → Run), each collapsible, with key questions, activities, outputs, AI / vibe-coding watch-outs and an exit checklist
- **7 decision gates** (G0–G6), go / no-go points with explicit criteria
- **6 always-on rails**: security, governance & compliance, AI harness & tooling, data, cost & FinOps, people & change
- **Build methodology** ("governed vibe engineering"): explore vs engineer mode, the Guided Build Loop, rigour by risk tier
- **12 build principles** to check before development starts
- **Decision toolkit**: a TCO calculator and a weighted build-vs-buy scorecard, both running entirely in the browser
- **Roles & RACI** and a **glossary**

## Make your own version

All content lives in [`assets/data.js`](assets/data.js). Fork the repository, edit that one file (phases, checks, roles, criteria, glossary) and publish with GitHub Pages. No build step, no dependencies: plain HTML, CSS and JavaScript.

Run locally with any static server, for example:

```
python -m http.server 8000
```

## Publishing on GitHub Pages

Repository → Settings → Pages → Build and deployment → Source: **Deploy from a branch**, Branch: **main**, folder **/ (root)**.
